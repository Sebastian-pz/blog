The engagement is described in [Validating job profiles with VBA during a platform migration](/en/post/i-worked-for-multinational-using-programming-visual-basic-for-apps). This note is about doing it without knowing the language, and with little information on the way in.

They contacted me without the detail. I knew data had to be unified. I did not know which company, or which fields, until I was inside.

The user was human resources, and the result carried legal weight: it said whether a person met the job profile. Every field had to match its source, because the record was going to be used in an audit.

The procedure replaced a manual search. Rebuilding one regional employee's record took hours. Afterward, the lookup was by name, national ID, or email, and the consolidated file came back in seconds.

I did not know Visual Basic. Adapting took less time than I expected because the problem was data and rules: read workbooks, compare them with the job profile, and write two lists. VBA was the language available in Excel, which is where the information already lived.

The code solves the case and mixes file reading with the business rule. If I did it again, I would separate those two parts. The deliverable was still used.

Taking the job without knowing the language was worth it for the domain. I saw how a profile is validated when the data is not in a database, but in files.

I hope the next audit cycle does not find them with the workbooks scattered again.
